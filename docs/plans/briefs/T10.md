# T10: Access audit (fails closed)
P3 · est 3 h · agreed · 2026-11-01

**Why:** NFR3, A10 → without it nobody can tell who viewed which vehicle's documents, and personal data could leave the service with no record.

## Done when
1. Given any search, when `search(vin, caller)` finishes calling the sources, then exactly one row is written with the caller, full VIN, trace ID, outcome, each source's status and the document count. That includes `FAILED` searches.
2. Given the audit insert fails, then `search` throws `AuditUnavailableException`, so no documents are returned. The exception has no cause and no VIN.
3. Given no active span, then the row is still written, with `trace_id` `no-trace`.
4. Given the application's settings, then a database connection is waited for at most 1 s.
5. Given an invalid VIN, then no row is written: `Vin.parse` rejects it before `search` can run. T12 proves this end to end.

## Tests (written first)
- `DocumentSearchServiceTest`: `auditsOncePerSearch`, `auditsFailedSearches` (#1), `failsClosedWhenAuditFails` (#2), `writesNoTraceMarkerWithoutSpan` (#3); `AuditRepositoryIT` (Testcontainers PostgreSQL): `savesOneRowPerSearch` (#1), `waitsAtMostOneSecondForAConnection` (#4); `DocumentControllerIT.returns400ForInvalidVin` in T12 also checks for no row (#5)
