# T14: Tracing
P5 · est 2 h · done · 2026-11-03

**Why:** NFR6, NFR3 → without it a slow or failed request can't be followed to the source at fault, and once traces leave the service, the automatic HTTP spans would carry the full VIN.

## Done when
1. Given a search for `…0001`, then `sales.fetch` and `service.fetch` are children of the request span with its trace ID, their time ranges overlap, and each source's HTTP client span is a child of its source span.
2. Given a search, then `X-Request-Id` equals the request span's trace ID, and so does the audit row's `trace_id`.
3. Given a search, then each WireMock request carries a `traceparent` header with that trace ID.
4. Given a search for `…0002` (Service times out), then `service.fetch` has `result=timeout`, `fallback.read` and `audit.save` exist, source spans carry `source`, `result`, `document_count` and the masked VIN, and no span name, attribute or event holds the full VIN. There is no `http.url`, and errors give the exception class only.
5. Given a source past the deadline, then its span ends at the deadline with `result=timeout`, even though the HTTP call runs on.
6. Given `docker compose up`, the app running and a demo search, then Jaeger (16686) shows the trace as in design doc §6.2.

## Decisions
| Question | Answer | Source |
