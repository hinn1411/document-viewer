# T14: Tracing
P5 · est 2 h · done · 2026-11-03

**Why:** NFR6, NFR3 → without it a slow or failed request can't be followed to the source at fault, and once traces leave the service, the automatic HTTP spans would carry the full VIN.

## Done when
1. Given a search for `…0001`, then `sales.fetch` and `service.fetch` are children of the request span with its trace ID, their time ranges overlap, and each source's HTTP client span is a child of its source span.
2. Given a search, then `X-Request-Id` equals the request span's trace ID, and so does the audit row's `trace_id`.
3. Given a search, then each WireMock request carries a `traceparent` header with that trace ID.
4. Given a search for `…0002` (Service times out), then `service.fetch` has `result=timeout`, `fallback.read` and `audit.save` exist, source spans carry `source`, `result`, `document_count` and the masked VIN, and no span name, attribute or event holds the full VIN. There is no `http.url`, and errors give the exception class only.
5. Given a source past the deadline, then its span ends at the deadline with `result=timeout`, even though the HTTP call runs on.
6. Given `docker compose up`, the app running and a demo search, then Jaeger (16686) shows the trace as in design doc §6.2.

- By hand (#6), 2026-11-03: with `docker compose up` and the app running, Jaeger showed both demo traces as in §6.2, with no full VIN anywhere. For `…0002`, `service.fetch` had `result=timeout` (1.5 s), and its client span was an error naming only `ResourceAccessException`

## Decisions
| Question | Answer | Source |
|---|---|---|
| Your choice | A source span starts on the request thread and ends with the outcome, so its duration and `result` match the response and T13's metric. One `ObservationFilter` drops `http.url` from server and client spans; the `uri` template stays. Found while building: a failed source call's client span also got Spring's error message, which holds the URL, before any filter runs, so Boot's client-span handler is replaced by one that records the class only. Only the 4 tests from 07 | you |
| Spans | Made with the `Tracer`, as `TraceIds` already is, not the Observation API, which would add a timer per span next to T13's metrics. `fallback.read` only when a source failed; `audit.save` around the insert | 07; default |
| Threads | Changed while building: each source span is put in scope on its virtual thread, instead of wrapping the executor. A wrapper would carry the request span, so the HTTP client span would still need its source span put in scope. Source-thread log lines get the trace ID either way, which T15 left to T14 | 07; T15 |
| Export | Jaeger `jaegertracing/jaeger:2.21.0` (v2; v1 `all-in-one` is end of life), in Compose (16686, 4318). OTLP trace export on, sampling stays 1.0. Tests use the in-memory exporter and never reach 4318. `test-compose.sh` also needs 16686 and 4318 free | 07 |
