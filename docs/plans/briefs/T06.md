# T06: Result merger
P1 · est 2 h · agreed · 2026-10-30

**Why:** FR3, A6, A7 → without it there's no single list: order would vary between calls, and nothing would decide `COMPLETE`, `PARTIAL` or `FAILED`.

## Done when
1. Given documents from two sources, when merged, then the list is newest first, undated documents come last, and ties are broken by `source`, then `sourceDocumentId`, so the order never varies.
2. Given the same `sourceDocumentId` twice from one source, then it appears once. Given it once each from two sources, then both are kept.
3. Given all sources `OK`, then `outcome` is `COMPLETE` and `partial` is false. Given any other mix with at least one `OK` or `STALE`, then `PARTIAL` and true. Given no `OK` or `STALE`, then `FAILED` and true.
4. Given any merge, then every document keeps its `source` and `stale` flag, and every `SourceOutcome` stays in `sources`, including `UNAVAILABLE` ones.
5. Given a `SourceOutcome`, then `OK` has no `reason` or `dataAsOf` and no stale documents; `STALE` has both and only stale documents; `UNAVAILABLE` has a `reason` and no documents. Anything else throws `IllegalArgumentException`.

## Decisions
| Question | Answer | Source |
