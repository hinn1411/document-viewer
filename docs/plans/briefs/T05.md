# T05: VIN value object
P1 · est 1 h · agreed · 2026-10-30

**Why:** FR1, A2, A10 → without it, invalid VINs reach the sources and the audit, and full VINs can leak into logs.

## Done when
1. Given `" wvwzzz1jzxw000001 "`, when it's parsed, then the value is `WVWZZZ1JZXW000001`.
2. Given a length other than 17, a null or blank input, a VIN containing I, O or Q in either case, or any other character outside `[A-HJ-NPR-Z0-9]`, when it's parsed, then `InvalidVinException` is thrown.
3. Given a valid VIN, then `masked()` returns `WVW**********0001`.
4. Given a `Vin` or a rejected input, then neither `toString()` nor the exception message contains the full VIN.
5. Given invalid input passed straight to the `Vin` constructor, then `InvalidVinException` is thrown, so no invalid `Vin` can exist.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Shape | Record `Vin(String value)` with `parse` and `masked()`; both classes in `search/model/` | 05, 06 T05 |
| Rules | Trim, upper-case, 17 characters from `[A-HJ-NPR-Z0-9]`; check digit not enforced | A2, 05 |
| Where validation lives | The record's compact constructor, because a record's constructor is public and `parse` alone could be bypassed | invariant 1 in 05 |
| `toString()` | Returns the masked form, because a record's default would print the full VIN | `java-code.md` privacy rule, A10 |
| Exception type | Unchecked, with a fixed message; T12 maps it to 400 `invalid-vin` | 05 error table |
