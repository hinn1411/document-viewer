# T15: Structured logs
P5 · est 2 h · done · 2026-11-02

**Why:** NFR3, NFR6 → without it an alert can't be traced to a failing source from the logs, and source failures and failed audits leave no log line at all.

## Done when
1. Given a partial search (`…0002`), then exactly one `INFO` line `documents.search completed` is written. It's valid JSON with `userId`, `dealershipId`, masked `vin`, `httpStatus`, `outcome`, `durationMs`, `sources[]` (`source`, `status`, `reason`, `latencyMs`, `documentCount`), and a `traceId` equal to `X-Request-Id`.
2. Given a failed audit, then no summary is written.
3. Given any search, then no log line contains the full VIN, a document title or a URL.
4. Given a source error or a timeout, including one that passes the deadline, then a `WARN` line names the source and reason, with no response body.
5. Given a failed audit or an unexpected exception from a source, then an `ERROR` line gives the exception's class name only.

## Tests (written first)
- `LoggingIT` (full app, Testcontainers, WireMock, `OutputCaptureExtension`): `writesOneJsonSummaryPerRequest` (#1), `neverLogsFullVin` (#3), `logsSourceFailureAtWarn` (#4), `logsAuditFailureWithClassOnly` (#2, #5)
- `DocumentSearchServiceTest`: `logsTimeoutPastDeadlineAtWarn` (#4), `logsUnexpectedSourceFailureWithClassOnly` (#5)

## Decisions
| Question | Answer | Source |
|---|---|---|
| Your choice | The summary covers searches with a result: 200s and the all-sources-down 503. A failed audit has its `ERROR` line, and 400/401 have no line. An open breaker logs no `WARN` per request: the summary shows `CIRCUIT_OPEN`, and the state-change `WARN` marks the transition | you |
| Format | `logging.structured.format.console: logstash`, always on, with SLF4J `addKeyValue`. Probed: flat `level`, `traceId` and `spanId`, closest to §6.2, but it writes `@timestamp`, not `timestamp`, and adds a few standard fields. `sources[]` must be a list of maps, as a record is written as its `toString` | §6.2, 07; probe |
| Where | The API layer writes the summary, as only it knows the HTTP status. `WARN`s are written in `search()` after the join, so they carry the trace ID and cover deadline timeouts, which never enter `call()` | default |
| Existing lines | All `key=value` lines become JSON fields with no duplicates, including the breaker and 500 lines, which 07 doesn't list. Levels stay the same | 07 |
| Not tested, by your choice | The all-sources-down 503's summary, no `WARN` for an open breaker, the fallback lines' JSON fields, and titles in #3 (no log line is given one). All are still built | you |
