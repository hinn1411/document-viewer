# T12b: One circuit breaker per source
P4 · est 2 h · done · 2026-11-01

**Why:** NFR1, NFR2 → while a source is stalled, every request waits 1.5–2 s for a call that will fail, and that load keeps reaching a source already in trouble.

## Done when
1. Given a source's breaker is open, when a search runs, then no call reaches that source and its reason is `CIRCUIT_OPEN`.
2. Given one breaker is open, then the other source still answers `OK` and the result is partial.
3. Given a breaker is open and a copy under 24 h old exists, then that source is `STALE` with reason `CIRCUIT_OPEN`.
4. Given both breakers are open and no copy exists, then the endpoint returns 503 with `sources[]`, and a `FAILED` audit row is written.
5. Given repeated 503s, 500s, reset connections or timeouts from a source, then its breaker opens. Given repeated 404s or unreadable responses, then it stays closed.
6. Given a half-open breaker and a recovered source, then the trial calls close it.

## Tests (written first)
- `DocumentSearchServiceTest`: `skipsCallWhenBreakerOpen` (#1), `otherSourceUnaffectedWhenBreakerOpen` (#2), `servesStaleCopyWhenBreakerOpen` (#3)
- `DocumentControllerIT`: `returns503AndAuditsWhenBothBreakersOpen` (#4). `SourceCircuitBreakerIT` (real adapters, WireMock): `opensAfterRepeated503s`, `opensWhenSourceKeepsFailing`, `doesNotOpenWhenSourceAnswered` (#5), `closesAfterSourceRecovers` (#6)

## Decisions
| Question | Answer | Source |
|---|---|---|
| Your choice | A breaker per source, not on the endpoint: an endpoint breaker would reject requests a copy could answer, and skip the audit. See [ADR 0001](../../adr/0001-circuit-breaker-per-source.md) | you |
| Library | `resilience4j-circuitbreaker` 2.4.0, the core library only. No annotation, because an annotation behind a proxy failed silently in T07, and its Spring Boot 4 starter support is unverified | T07; plan |
| Placement | In `DocumentSearchService.call`: breaker, then retry, then HTTP, so one search counts once. Breakers are created from the source's name, so a new source still needs one adapter. Any 5xx, timeout or I/O failure counts (your decision after review, wider than the retry rule). A 4xx or an unreadable response doesn't, because it may be one VIN | NFR5; plan |
| Settings | New `CircuitBreakerProperties` for `docviewer.circuit-breaker`: 60 s time window, 10 calls minimum, 50% failure and slow rates, 1.5 s slow call, 30 s open, 3 trial calls, 60 s half-open limit (from review: 10 s reopened a recovered source at low traffic). A separate record leaves `DocViewerProperties` and its tests alone | plan; default |
