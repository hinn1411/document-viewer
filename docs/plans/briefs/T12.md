## Decisions
| Question | Answer | Source |
|---|---|---|
| Your choice | Identity headers are read in the controller with `@RequestHeader(required = false)`, with no `CallerFilter`. A missing or blank value throws an exception that `ProblemHandler` maps to 401. `01`, `05` and `java-code.md` change to match | you |
| Errors | `ProblemHandler` extends `ResponseEntityExceptionHandler`, so the catch-all doesn't turn Spring's 404 or 405 into 500. `FAILED` throws an exception carrying `sources[]`, so all error mapping stays in one class. `type` values are 05's | 05; default |
| Headers | One filter on every path sets both headers before the chain runs. The request ID is the current trace ID, or `no-trace` with no span, using the audit's rule so the two can't differ | §6.2, T10 |
| Logging, privacy | The 500 handler logs at `ERROR` by exception class only, or a 500 leaves no trace; T15 converts it to JSON. Spring fills a problem's `instance` with the request path, so an error body contains the VIN its caller sent. It isn't logged, so it stays | 07, NFR3; default |
| Not tested, by your choice | The 500 handler (returns no details, logs by exception class only, as in 05) and 401 being checked before the VIN. Both are still built. Swagger UI is checked by hand | you |
