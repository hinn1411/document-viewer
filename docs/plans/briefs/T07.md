# T07: Sales System adapter
P2 · est 3 h · done · 2026-10-31

**Why:** FR2, A3, A4, NFR5 → without it there's no real source: Sales' nested shape, dates and codes never reach the common format, and a slow or failing Sales system has no timeout or retry.

## Done when
1. Given the nested deals response, when `fetch` runs, then each document becomes a `Document` with `id()` `SALES:INV-1001`, a mapped `type` (`INV`, `ORD`, unknown → `OTHER`), and `createdOn` as the start of that day in the dealership zone, in UTC. Given `deals: []`, then the list is empty.
2. Given an item with no `docRef`, a link that isn't `https`, or a `createdOn` that isn't a real `dd/MM/yyyy` date, then that item is dropped and the others are kept. Given no `createdOn`, then the item is kept undated.
3. Given a body that can't be parsed, has no `deals` or has a null array entry, then `fetch` throws `SourceException(ERROR)` with no retry. Given a 404, the same. The exception and its causes never contain the VIN.
4. Given 503 then 200, then the call succeeds after one retry. Given 503 twice, then it throws `ERROR` and WireMock saw exactly 2 requests.
5. Given a read longer than 1.5 s, then it throws `TIMEOUT` and WireMock saw 1 request.
6. The retry predicate is true for 502, 503, 504 and refused connections, and false for timeouts and other failures.

## Decisions
| Question | Answer | Source |
|---|---|---|
| 404 | `ERROR`, no retry: no documents is already 200 with `deals: []`, and a 404 could be a wrong URL | you |
| Bad data | One bad item is dropped, including an impossible date (`31/02/2025`, so strict parsing); a missing date is undated. An unreadable response, no `deals` or a null array entry (your call) is `ERROR`, not "no documents". Accepted limits: a wrong-typed field fails the whole body; a missing `name` keeps the item with a null title | §4.2 row 5, A7 |
| Test setup | Small Spring context for the `@Retryable` proxy, without PostgreSQL. Happy path uses the `mocks/sales` stubs | 06 T07 design note; default |
